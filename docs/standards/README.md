# 工程规范

本目录规定说明书核对系统的统一工程质量要求：

- [编码规范](./编码规范.md)
- [Review 规范](./Review规范.md)
- [测试规范](./测试规范.md)

## 适用顺序

出现冲突时按以下优先级执行：

1. `docs/implementation0plan/00_说明书核对系统_冻结方案.md`
2. 当前获准实施的阶段方案
3. 本目录工程规范
4. 框架默认约定和个人偏好

未经用户明确允许，不得通过修改冻结方案解决实现冲突。

## 通用质量门禁

每次 Coding 必须满足：

1. 只实现当前获准阶段。
2. 完成自检和代码 Review。
3. 修复所有 P0、P1 问题。
4. 执行本阶段测试和此前阶段回归测试。
5. Ruff、pytest、前端类型检查和生产构建通过。
6. 冻结方案 SHA-256 保持不变。
7. 输出实际执行的测试命令、结果和未解决问题。
8. 停止并等待用户授权下一阶段。

禁止以硬编码结果、吞异常、跳过测试或降低验收条件的方式制造“完成”。
