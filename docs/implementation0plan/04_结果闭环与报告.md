# 阶段 4：结果闭环与报告

## 阶段目标

完成用户可操作的任务、进度、结果、证据、人工复核和报告闭环，使一项核对任务能够从上传到最终导出完整运行。

## 开始条件

- 阶段 3 已完成 Review 和全部测试。
- 用户明确批准进入阶段 4。
- 冻结方案哈希不变。

## 实现范围

### 1. 人工复核与审计

实现：

- `review_record` 表和必要迁移。
- `check_result.final_conclusion` 与人工改判字段。
- `POST /tasks/{task_id}/results/{result_id}/review`。
- 保留 `system_conclusion`，禁止覆盖或删除。
- 从 `FAIL`、`ERROR`、`NEEDS_REVIEW` 改为 `PASS` 必填说明。
- 关键项任何改判必填说明。
- 复核人来自 `REVIEWER_NAME`。
- 不允许向既有任务追加或替换原始材料。

### 2. 报告

实现 `report` 表、生成服务与 API：

- `POST /tasks/{task_id}/reports`。
- `GET /tasks/{task_id}/reports/{report_id}`。
- Excel：`Summary`、`Results`、`Evidence`、`ReviewLog`、`Metadata`。
- JSON：冻结方案规定的完整结构。
- 报告使用生成时的最终结论快照。
- 不导出 API Key、完整提示词、图片 Base64 或绝对路径。
- 报告失败不改变核对任务状态。

### 3. 任务列表与详情前端

实现：

- 任务列表：名称、时间、状态、阶段、进度和结果统计。
- 新建任务页：分区上传、前端基础校验和后端错误展示。
- 进度页：SSE 阶段和进度；断线后先查询任务再重连。
- 清单确认页完善。
- 结果页：分页及按结论、类型、等级、人工修改筛选。
- 结果详情：要求、说明书证据、依据证据、差异和理由。
- DOCX 逻辑位置、PDF 页码、图片缩略图。
- 人工改判表单及必填约束。
- 报告生成与下载。

### 4. 删除与生命周期

实现：

- `DELETE /tasks/{task_id}`。
- 前端二次确认。
- 数据库事务与文件清理协调。
- 文件清理失败显式提示并可重试。
- `RETENTION_DAYS` 留空时不自动清理。
- 若实现自动清理，只能整项删除。

### 5. 统一错误与可观测性

- 错误响应统一为 `code`、`message`、`details`、`request_id`。
- 业务日志采用冻结方案字段。
- 页面日志摘要来自业务事件，不回显服务端原始日志。
- 所有用户材料展示执行 HTML 转义。

## 明确不做

- 登录、用户、角色或权限。
- 生产部署和对象存储。
- 历史模板库与跨任务复用。
- 自动学习和提示词自动更新。
- 修改原始说明书。
- 额外报告格式。

## 必做测试

### 后端

- 每种人工改判及说明必填规则。
- 系统结论永不被覆盖。
- Excel 工作表、列、值、证据和复核历史完整。
- JSON Schema 和敏感字段排除。
- 报告快照一致性。
- 删除成功、文件失败、数据库失败和重试。
- 统一错误结构和请求 ID。

### 前端

- 上传、清单确认、进度、结果筛选、详情、复核和报告的关键交互。
- SSE 断线恢复。
- 错误态、空态、加载态和 `COMPLETED_WITH_ERRORS`。
- 原文内容不会作为 HTML 执行。
- 类型检查和生产构建。

### 端到端

- 使用 Fake Agent 从新建任务走到 Excel/JSON 下载。
- 人工改判后页面与两类报告一致。
- 删除任务后 API、数据库和磁盘均不可再访问。
- 阶段 1～3 全量回归。

## Review 清单

- 是否覆盖了系统原始结论。
- 高风险改判是否绕过说明必填。
- 报告是否泄露绝对路径、密钥或完整提示词。
- 下载接口是否接受任意磁盘路径。
- 用户文档内容是否可能触发 XSS。
- 删除失败是否留下不一致且无告警。
- 是否引入了用户系统或生产部署范围。

## 完成门槛

- Fake Agent 下完整业务闭环可由浏览器执行。
- 页面、数据库、Excel 和 JSON 的最终结论一致。
- 证据和复核历史完整可追溯。
- 删除和下载路径安全测试通过。
- Review 无 P0/P1，冻结方案哈希不变。
- 提交阶段报告并等待阶段 5 授权。
