# 阶段 1：材料接入与文档解析

## 阶段目标

完成从任务创建、材料落盘、输入校验到统一 `DocumentGraph` 的可信数据入口，为后续核对清单和证据匹配提供稳定数据。阶段结束时不调用模型、不生成核对项、不判断核对结论。

## 开始条件

- 当前工程骨架测试全部通过。
- 冻结方案哈希与执行总则一致。
- 用户明确允许开始阶段 1。

## 实现范围

### 1. 数据模型与迁移

补齐本阶段所需表和枚举：

- `verification_task` 的冻结方案字段。
- `task_file`。
- `document_block`。
- `template_comment`。
- 必要的解析状态、文件类别和警告结构。

要求：

- 所有时间使用 UTC。
- 文件只保存安全相对路径和 SHA-256，不把二进制写入 SQLite。
- 新迁移可升级、可回退。

### 2. 任务创建与文件接入

实现：

- `POST /api/v1/tasks` multipart 完整材料上传。
- `GET /api/v1/tasks`。
- `GET /api/v1/tasks/{task_id}`。
- 任务目录 `data/tasks/{task_id}/uploads`、`parsed`、`extracted`、`reports`。
- 每任务恰好一个说明书 DOCX、一个模板 DOCX、一个项目 JSON；依据 PDF/图片可为多个。
- 同任务 SHA-256 去重。
- 扩展名、MIME、魔数、文件大小和任务总量校验。
- 原始文件名只作元数据，磁盘文件名使用 UUID。

### 3. 安全处理

必须实现：

- 路径必须解析在当前任务目录内。
- 防止 Zip Slip、XML 外部实体、压缩炸弹和超大图片。
- 限制 DOCX 解压总量、XML 节点数、图片像素和文件数量。
- 上传失败时清理未完成的临时文件和数据库记录。
- 不在日志中输出完整材料内容。

### 4. 项目 JSON

实现冻结方案 `schema_version=1.0` 的 Pydantic Schema：

- 固定 `project` 字段。
- 一层 `attributes` 扩展字段。
- Unicode、键名空白和值的标准化副本。
- 原始内容保留用于审计。
- 核心字段为空不阻断任务；结构不合法阻断任务。

### 5. DOCX 解析

直接读取 OOXML：

- `word/document.xml`。
- `word/comments.xml`。
- `word/_rels/document.xml.rels`。
- `word/media/*`。

必须完成：

- 标题、段落、表格单元格、图片的有序块解析。
- `commentRangeStart`、`commentRangeEnd`、`commentReference` 与批注 ID 的精确关联。
- 批注圈选文本、标题路径、前后文和邻近图片定位。
- 无法支持的批注形态显式产生警告，禁止静默忽略。
- DOCX Locator 不承诺页码。

### 6. PDF 与图片解析

PDF：

- 使用 PyMuPDF 按页提取文本块、坐标和图片。
- 识别扫描型 PDF；必需依据阻断，可选依据警告后忽略。
- Locator 包含页码、矩形坐标和摘录。

图片：

- 检查可解码性、像素数和格式。
- 处理 EXIF Orientation。
- 生成受限尺寸副本并保留原图哈希。
- 不实现 OCR。

### 7. 解析 Workflow

只实现以下状态流：

```text
CREATED → VALIDATING → PARSING → GENERATING_CHECKLIST
```

阶段 1 暂不真正生成清单；解析成功后允许停在 `GENERATING_CHECKLIST` 的明确待实现边界。任务级阻断错误进入 `FAILED`。

## 明确不做

- 通用规则目录。
- LLM 核对项生成。
- 核对清单确认页。
- 证据匹配和任何 PASS/FAIL 判断。
- SSE 全量实现；只需数据库状态可查询。
- 报告和人工复核。

## 必做测试

### 单元测试

- 合法与非法项目 JSON。
- 文件签名、扩展名、大小、重复文件。
- 路径穿越、Zip Slip、外部实体和压缩炸弹。
- DOCX 普通段落、表格、嵌套标题、单段批注、跨 Run 批注、表格批注、邻近图片。
- 批注缺失结束标记、未知关系和损坏 DOCX。
- 文本型 PDF 与扫描型 PDF。
- 图片方向、超大像素和损坏图片。

### 集成测试

- 上传完整材料后数据库、任务目录和解析记录一致。
- 任一必需文件失败时任务进入 `FAILED` 且无孤立文件。
- 重新读取数据库可还原完整 DocumentGraph。
- Alembic 从空库升级并回退。

## Review 清单

- 是否有任何以原始文件名直接拼接路径的代码。
- 是否仅靠扩展名判断文件类型。
- 是否存在静默跳过批注或解析失败。
- 数据库与磁盘写入失败时是否可恢复。
- 是否把完整文件内容或密钥写入日志。
- 是否错误实现 DOCX 页码。
- 是否提前实现了阶段 2 及以后功能。

## 完成门槛

- 测试夹具中的每条批注均能定位到预期正文、表格或图片锚点。
- DocumentGraph 可序列化并从数据库还原。
- 所有安全负例得到确定错误码。
- Review 无 P0/P1。
- 冻结方案哈希不变。
- 向用户提交阶段报告并停止，等待阶段 2 授权。
