# 阶段 3 实施报告：证据匹配与核对执行

## 1. 实施结论

阶段 3 已按冻结方案完成，未进入阶段 4，未修改冻结方案。

本阶段形成了从已确认清单到可追溯系统结论的闭环：任务在本地单执行槽中串行调度，单任务内并行执行独立核对项；系统先匹配有限候选证据，再通过确定性规则、无工具文本 Agent 或无工具视觉 Agent 判断，并对高风险结果执行隔离复核。

## 2. 实现内容

### 2.1 数据与迁移

- 新增 Alembic 迁移 `20260926_0004`。
- 新增 `evidence`、`check_run`、`check_result`。
- 结果同时保存 `system_conclusion` 与初始 `final_conclusion`，为阶段 4 人工复核保留不可覆盖的系统结论。
- 运行记录保存输入哈希、原因码、候选证据 ID、模型名、提示词版本、耗时、Token、重试次数、差异、缺失信息和错误类型。
- 不保存 API Key、完整提示词或图片 Base64。

### 2.2 证据匹配

- 使用 Unicode 规范化、字段值精确匹配、中文字符二元组、英文 token 词频、标题路径、表格类型加权和图片关系结构生成候选。
- 每个来源的候选上限可通过 `MAX_EVIDENCE_CANDIDATES_PER_SOURCE` 配置，默认 8。
- `evidence_id` 由核对项与材料内稳定定位生成，不由模型生成。
- 项目 JSON、依据 PDF、依据图片默认无全局优先级；同一事实的显式键值冲突由程序输出 `NEEDS_REVIEW/SOURCE_CONFLICT`。
- 缺少目标或所需依据分别输出 `MISSING_TARGET_CONTENT`、`MISSING_SOURCE_DATA`。

### 2.3 四类执行通道

- `FIELD_RULE`：产品名称、型号、品牌和项目扩展属性等确定性值核对。
- `STRUCTURE_RULE`：语言、必要章节和模板结构要求。
- `SEMANTIC_AGENT`：基于有限文本候选的无工具结构化判断。
- `VISION_AGENT`：仅把候选图片在调用时临时编码给无工具模型，不落库 Base64。
- Agent 输出区分目标证据与来源证据，并包含原因码、差异和缺失信息；未知证据 ID 属于结构化输出错误。
- 确定性规则执行失败形成 `ERROR`，不会转交模型猜测。

### 2.4 独立复核与错误语义

- 所有 `CRITICAL` 模型项执行第二次独立判断。
- `NORMAL` 且首次为 `FAIL` 的模型项执行第二次独立判断。
- 第二次输入只含原要求与原证据，不含首次结论或理由。
- 两次判断不一致时输出 `NEEDS_REVIEW/MODEL_DISAGREEMENT`。
- 认证、超时、限流耗尽、结构化输出和内部错误映射为 `ERROR` 原因码，不伪装成业务待复核。

### 2.5 Workflow、恢复与 API

- 状态链为 `QUEUED → MATCHING_EVIDENCE → CHECKING → AGGREGATING → COMPLETED / COMPLETED_WITH_ERRORS`。
- `LocalTaskDispatcher` 使用进程级单执行槽保证任务间串行；全局模型信号量限制单任务模型并发。
- 确认和错误重试在 HTTP 响应后进入后台执行，不阻塞请求。
- 支持排队及活动任务取消、只重跑 `ERROR` 项、后端启动中断活动任务。
- 新增结果列表、结果详情、取消、错误重试和 SSE 进度接口。
- 新增基础结果页，支持错误重试、证据展开、SSE 更新和断线后 HTTP 查询恢复。
