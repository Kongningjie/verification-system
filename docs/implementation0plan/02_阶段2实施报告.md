# 阶段 2 实施报告

## 1. 实施范围

本阶段仅实现核对清单生成与确认，没有进入证据匹配或正式核对：

- 新增版本化通用规则注册表，覆盖产品名称、型号、品牌、目标市场、语言、必要章节和项目扩展属性。
- 新增无工具 Checklist Generator Agent、Pydantic 结构化输出、超时、临时错误重试、错误映射及调用元数据。
- 新增确定性 Fake Agent，普通自动测试不访问网络。
- 基于模板批注逐条生成动态项，支持拆分、通用规则映射建议、重复建议、缺失依据和等级告警。
- 新增核对项、乐观锁修订号和不可变清单版本快照。
- 新增核对项查询、编辑和确认 API。
- 新增核对清单确认页，支持来源查看、编辑、启停、等级调整、依据调整和确认。
- 清单确认后任务进入 `QUEUED`，不启动阶段 3 的正式核对。

## 2. 关键设计结果

- 模型只接收单条批注、圈选内容、标题路径、受限前后文、可用依据类型和通用规则摘要；不接收未批注模板全文。
- 文档内容在 Agent 系统指令中明确标记为不可信数据，Agent 不配置工具、Handoff、Session、MCP 或网络能力。
- 动态项若映射通用规则则保留批注来源；未映射项转换为 `CUSTOM_SEMANTIC`、`CUSTOM_VISUAL` 或 `CUSTOM_STRUCTURE`。
- 模型建议关键等级时，服务端再次校验批注是否包含法规、认证、安全、强制、禁止或不可缺失语义；不满足时降为普通项并产生告警。
- 多条批注疑似重复时只添加 `POSSIBLE_DUPLICATE`，不会静默删除任何批注项。
- 确认前前端会保存全部当前编辑；后端以项目版本号和清单修订号防止陈旧更新，确认后禁止原地修改。
- 模型阶段失败会将任务标为 `FAILED` 并保留已解析材料，错误不会伪装成空清单或业务待复核。
