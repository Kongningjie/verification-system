# 阶段 2：核对清单生成与确认

## 阶段目标

基于阶段 1 的解析结果，完成“通用规则 + 模板批注动态要求”的核对清单生成、用户编辑与不可变版本确认。阶段结束时仍不执行正式核对。

## 开始条件

- 阶段 1 已完成 Review 和全部测试。
- 用户明确批准进入阶段 2。
- 冻结方案哈希不变。

## 实现范围

### 1. 数据模型与迁移

实现：

- `check_item`。
- 核对清单版本或快照结构。
- 生成告警、来源类型、核对类型和严重等级枚举。
- 清单编辑的乐观锁版本号。

确认后的快照必须不可变；重新修改只能产生新版本，不能覆盖已确认内容。

### 2. 通用规则目录

使用版本控制内 YAML 或 JSON 配置实现规则注册表，至少包含：

- 产品名称。
- 型号。
- 品牌。
- 目标市场。
- 语言。
- 必要章节。
- 可由项目 JSON 确定的其他稳定字段。

每条规则必须符合冻结方案字段：`rule_id`、`version`、`name`、`description`、`check_type`、`default_severity`、`required_sources`、`applicability`、`executor`。

本阶段只生成清单，不实现 executor。

### 3. Agents SDK 适配层

实现本地 `openai-agents` 运行封装：

- 从 `.env` 读取 API Key、Base URL 和模型。
- 定义无工具 Checklist Generator Agent。
- 使用 Pydantic 结构化输出。
- 默认关闭 tracing。
- 统一超时、重试、错误映射和 Token/耗时元数据。
- 不使用 Handoff、多 Agent、Session、MCP、Web 或文件系统工具。

提供确定性的 Fake Agent，供无 API Key 的自动测试使用。

### 4. 动态批注核对项

每条批注只向模型提供：

- 批注文本。
- 圈选内容。
- 标题路径和有限上下文。
- 可用依据类型。
- 通用规则摘要。

输出必须符合冻结方案 `GeneratedCheckItem`。实现：

- 一条批注拆分多个独立要求。
- 多条批注提出合并建议但不静默删除。
- 无明确要求时生成带告警项，不跳过批注。
- 通用规则映射。
- `CRITICAL` 建议必须包含来源理由。
- 文档内容作为不可信数据，不可覆盖系统指令。

### 5. 清单生成 Workflow

实现：

```text
GENERATING_CHECKLIST → AWAITING_CHECKLIST_CONFIRMATION
```

模型失败必须产生可见技术错误；不得伪造空清单或把技术错误标为业务待复核。

### 6. 清单 API 与前端页面

实现：

- `GET /tasks/{task_id}/check-items`。
- `PATCH /tasks/{task_id}/check-items/{item_id}`。
- `POST /tasks/{task_id}/check-items/confirm`。
- 清单确认页：来源批注、圈选文本、名称、要求、类型、等级、依据和告警。
- 启用/停用、编辑、调整关键等级。
- 确认后任务进入 `QUEUED`，但阶段 2 不启动正式核对。

## 明确不做

- 全文自由生成要求。
- 从未批注模板正文推导特殊项。
- 证据检索。
- 规则、语义或图片核对。
- 二次独立判断。
- 结果页、人工复核和报告。

## 必做测试

### 单元测试

- 通用规则配置 Schema、唯一 ID 和版本。
- 每条模板批注都有输出或显式错误。
- 动态项拆分、映射、告警和关键等级建议。
- Pydantic 输出校验失败、超时、认证错误和重试。
- 清单状态与乐观锁。
- 已确认快照不可变。

### 集成测试

- Fake Agent 下完整生成清单。
- 真实 Agents SDK 契约测试可单独标记，需要本地 API Key 才运行。
- 用户编辑、停用、确认后生成正确版本快照。
- 后端重启后待确认清单仍可恢复。
- 阶段 1 全量回归。

## Review 清单

- 是否把普通模板正文送给模型自由生成要求。
- 是否存在批注被静默遗漏。
- 是否允许模型单方面确定最终关键等级。
- 是否把 API Key 或完整提示词写入日志或数据库。
- 是否启用了工具、Handoff、会话记忆或远程 tracing。
- 是否允许确认后原地修改清单。
- 是否提前实现正式核对。

## 完成门槛

- 测试模板的关键核对项召回率达到 100%。
- 所有批注都有清单项、合并建议或显式错误记录。
- 确认后的清单可重载且不可变。
- Fake Agent 流程无需网络可运行。
- Review 无 P0/P1，冻结方案哈希不变。
- 提交阶段报告并等待阶段 3 授权。
