# 阶段 3：证据匹配与核对执行

## 阶段目标

完成已确认核对清单的证据匹配、确定性规则核对、文本/视觉 Agent 判断、风险分级独立复核、并发和错误处理，形成可追溯系统结论。

## 开始条件

- 阶段 2 已完成 Review 和全部测试。
- 用户明确批准进入阶段 3。
- 冻结方案哈希不变。

## 实现范围

### 1. 数据模型与迁移

实现：

- `evidence`。
- `check_run`。
- `check_result` 的系统结论部分。
- 结果、原因码、运行类型和证据角色枚举。

保存输入哈希、模型名、提示词版本、Token、耗时、重试次数和错误类型；不保存 API Key、完整提示词或图片 Base64。

### 2. 证据匹配

实现冻结方案限定的非向量检索：

1. 字段别名、规范化值和精确匹配。
2. 标题路径、批注锚点和文档顺序邻近性。
3. 中文字符 n-gram、英文 token 的 BM25/词频排名。
4. 表格行列标题匹配。
5. 图片与段落、标题和关系 ID 的结构关联。
6. 可选的有限候选 LLM 重排；禁止网络和全文件系统搜索。

每个候选生成稳定 `evidence_id`。模型只能从候选 ID 中引用证据，返回未知 ID 必须判为结构化输出错误。

### 3. 依据冲突与缺失

- 模板和说明书不得作为事实权威来源。
- 项目 JSON、认证 PDF、ID 图默认无全局优先级。
- 指定依据优先规则只来自确认后的核对要求。
- 同一事实依据冲突：`NEEDS_REVIEW/SOURCE_CONFLICT`。
- 说明书目标缺失：`MISSING_TARGET_CONTENT`。
- 依据缺失：`MISSING_SOURCE_DATA`。

### 4. 四类执行通道

实现：

- `FIELD_RULE`。
- `STRUCTURE_RULE`。
- `SEMANTIC_AGENT`。
- `VISION_AGENT`。

规则通道不得在无法执行时转交模型猜测。Agent 使用统一 `AgentJudgement`，只允许输出 `PASS`、`FAIL`、`NEEDS_REVIEW`；`NOT_APPLICABLE` 和 `ERROR` 由程序控制。

### 5. 风险分级独立复核

- 所有 `CRITICAL` 模型项执行第二次独立判断。
- `NORMAL` 且首次 `FAIL` 的项目执行第二次独立判断。
- 第二次不得看到第一次结论或理由。
- 不一致时输出 `NEEDS_REVIEW/MODEL_DISAGREEMENT`。
- 保存两次独立 `check_run`。

### 6. Workflow 与本地调度

实现：

```text
QUEUED → MATCHING_EVIDENCE → CHECKING → AGGREGATING
                     ↘ COMPLETED / COMPLETED_WITH_ERRORS
```

同时实现：

- `LocalTaskDispatcher`：任务之间串行。
- 单任务内部异步并发，模型默认并发 3。
- 超时 90 秒、最多重试 2 次、指数退避和限流等待。
- 后端重启将活动任务标记为 `INTERRUPTED`。
- `POST /tasks/{task_id}/cancel`。
- `POST /tasks/{task_id}/retry-errors`。
- 内存事件总线和最小 SSE 事件。

### 7. 结果查询基础 API

实现：

- `GET /tasks/{task_id}/results`。
- `GET /tasks/{task_id}/results/{result_id}`。
- 按结论、类型和严重等级筛选。
- 返回系统结论和证据详情；本阶段不实现人工改判。

## 明确不做

- 用户人工复核写入。
- Excel/JSON 报告。
- 最终结果完整交互页面。
- 自动学习或更新规则。
- 任务间并行。
- 向量数据库、Embedding 或外部搜索。

## 必做测试

### 单元测试

- 各检索策略的排序与上限。
- 证据 ID 白名单校验。
- 依据冲突、目标缺失和依据缺失。
- 四类通道成功、失败和错误。
- 五类最终结论及原因码映射。
- 关键项与普通 FAIL 的二次判断。
- 二次判断输入不含首次结论。
- 并发上限、超时、重试、取消和重启中断。

### 集成测试

- Fake Agent 完成已确认任务至 `COMPLETED`。
- 单项技术失败形成 `ERROR` 和 `COMPLETED_WITH_ERRORS`。
- 失败项重试只重跑 `ERROR`。
- 两个任务按队列串行，单任务内并发不超过配置。
- SSE 断线后通过任务查询恢复最新状态。
- 阶段 1、2 全量回归。

### 真实模型契约测试

在用户提供可用 `.env` 后单独执行：

- 文本结构化输出。
- 图片输入。
- 三路并发。
- 认证、限流和超时错误映射。
- 独立复核隔离。

真实 API 测试未执行时必须明确报告，不能以 Fake Agent 结果代替。

## Review 清单

- 模型是否可能引用候选列表外的证据。
- 是否有任何无证据 PASS/FAIL。
- 是否把技术错误转换成 `NEEDS_REVIEW`。
- 确定性规则是否被 LLM 覆盖。
- 来源冲突时是否擅自选择权威材料。
- 第二次判断是否泄露第一次结论。
- 并发限制是否跨整个进程生效。
- 是否启用任务间并发、外部工具或向量数据库。

## 完成门槛

- Fake Agent 端到端产生完整、可追溯系统结论。
- 所有结论引用有效 evidence ID。
- 五类结论与任务最终状态语义正确。
- 并发、超时、重试和取消测试通过。
- Review 无 P0/P1，冻结方案哈希不变。
- 提交阶段报告并等待阶段 4 授权。
